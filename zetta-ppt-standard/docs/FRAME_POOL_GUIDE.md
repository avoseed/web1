# 프레임 풀 읽기·갱신 절차

프레임 풀은 그간의 보고 자료(정기협의체, 스티어링 커미티, 지주 보고, 재협상 보고, 보고.db)에서 모은 내부 프레임(F-번호)과, 컨설팅·해외·국내 기업 공개 덱에서 뽑아 지주 보고 양식으로 바꾼 외부 레퍼런스(E-번호)로 이루어진다. 원본은 클라우드 문서 하나이고, 이 스킬과 프로젝트 문서는 사본이다. 풀은 계속 바뀌므로 **작업할 때마다 원본을 읽고**, 새 프레임·사례·수정이 생기면 **Claude가 스스로 원본을 고친다.**

## 2. 읽기 (장표 기획 때마다)

1. docs 도구가 있으면 docs 스킬(또는 docs `guide`)을 먼저 불러온 뒤 읽는다.
2. 개요 탭 본문을 outline으로 읽어 유형별 번호 범위와 **갱신 이력**을 확인한다.
3. 이 장이 답할 질문으로 유형을 고른다.

   | 이 장이 답할 질문 | 유형 |
   |---|---|
   | 전체 그림, 오늘 다룰 것, 과제 구도는? | 1. 요약·전체 구도 |
   | 실적이 어떤가, 목표 대비 어디쯤인가? | 2. 실적·현황 점검 |
   | 왜 이렇게 됐나, 어디서 변했나? | 3. 원인 분석 |
   | 시장·경쟁사·고객은 어떤가? | 4. 시장·경쟁·고객 진단 |
   | 진단 결과 무엇을 해야 하나? | 5. 진단 → 대응 연결 |
   | 목표를 무엇으로 얼마나 채우나? | 6. 목표·계획 분해 |
   | 언제 무엇을, 어디까지 했나? | 7. 실행·일정·진척 |
   | 어느 안을 고를까, 협상 조건은? | 8. 대안·협상·의사결정 |
   | 이것이 무엇이고 어떻게 생겼나? | 9. 대상 소개·구조·증빙 |

4. 관계 색인 탭의 판별표로 이 장의 논리 관계(대비, 인과, 분해, 순서, 위계, 대응, 수렴, 분기, 병렬, 추적)를 정하고, 관계별 색인에서 F-번호 후보를 뽑는다.
5. 외부 레퍼런스 탭에서 같은 관계의 E-번호를 대안으로 찾는다: `{"kind":"search","text":"<관계>"}` 또는 키워드(예: 워터폴, 쉐브론, 받침). 시각 장치 열이 도형 구현 지시이므로 반드시 함께 읽는다. 탭이 크므로 전체를 한 번에 읽지 않는다.
6. 프레임 풀 탭을 outline으로 읽고, 고른 유형의 표만 `{"kind":"view","parentId":"<그 표 id>"}`로 읽는다. 특정 프레임은 `{"kind":"search","text":"F-0xx"}` 또는 키워드 검색. 문서 전체를 한 번에 읽지 않는다.
7. docs 도구가 없으면 Artifact `read`로 원본을 읽는다. 그것도 안 되면 기억이나 옛 사본으로 프레임 후보를 내지 않고, 프레임 풀 원본을 읽지 못했다고 사용자에게 알린 뒤 멈춘다. 사용자가 프레임 풀 PDF를 첨부하면 그 파일로 진행하고 답변에 "첨부한 프레임 풀(날짜) 기준"이라고 한 줄 밝힌다.

## 3. 쓰기 (프레임 후보 제시)

1. 후보 2~3개를 고른다. 관계 색인에서 이 장의 관계에 해당하는 프레임을 출처 구분 없이 한꺼번에 놓고 고른다(프레임 풀 탭 0절 사내 보고 템플릿 F-207~232, 1~9절 기존 F, 외부 레퍼런스 E). 같은 유형 안에서만 고르지 말고 관계가 겹치는 다른 유형도 본다.
   - **선정 기준은 적합도**: 이 장의 질문과 관계에 가장 맞는 배치를 고른다. 출처로 후보를 미리 거르지 않는다.
   - **사내 자료 우선(동점 처리와 최소 1개)**: 적합도가 비슷하면 사내 보고 템플릿(F-207~232) → 기존 F(사내 보고 기반) → 외부 E 순으로 고른다. 후보 2~3개 중 1개 이상은 사내 보고 기반(F-번호)으로 채우되, 맞는 것이 없으면 그 사실을 적고 외부 E로 채운다. 외부 E가 분명히 더 맞으면 1안으로 올려도 된다.
   - **편중 점검**: 후보 2~3개가 한 출처에서만 나왔거나, 같은 덱·같은 대화에서 앞 장과 같은 프레임이 다시 뽑혔으면 다른 출처를 한 번 더 훑어 대안을 찾는다. 다시 봐도 그 프레임이 가장 맞으면 그대로 쓰고 이유를 한 줄 적는다. 경영실적 8종(F-207~214)은 정례 실적 표를 옮기는 양식이라 반복해도 된다.
   - **사내 템플릿의 쓰임**: 배치보다 사내 보고 문법(표 형식, 결론 밴드, 입력 가이드의 근거 요건)이 핵심이다. 다른 프레임을 골라도 해당 템플릿의 주의 열(근거 수치, 1:1 대응, 출처 표기)은 적용한다.
2. 후보마다 다음을 적는다: F-번호(또는 E-번호)와 이름 / 관계 / 쓸 구조 도형(시각 장치 열 기준, 구현 함수 `frames.s_*`) / 이 내용에 맞는 이유(이 장의 논리 관계와 프레임의 "이런 관계일 때" 대응) / 배치 요지를 이 내용으로 바꾼 모습 / 사례 장표(덱 약어 + 쪽) / 주의 항목 중 이 내용에 걸리는 것.
3. 사용자가 고르기 전에는 서식 마무리(폰트·여백·색·정렬)에 시간을 쓰지 않는다. Claude의 역할은 기획과 프레임·설명틀 제시다.
4. 하나의 정답 양식은 없다. 이전 장표에서 쓴 프레임을 습관적으로 반복하지 않는다.
5. 기존 덱에 들어갈 장표나 사용자가 준 원안을 고치는 작업은 원안 구조를 유지한다. 이때 프레임 풀은 보완 아이디어로만 쓴다.

## 4. 갱신 (Claude가 스스로, 필요할 때마다)

### 언제 갱신하나

1. 사용자가 장표·이미지·덱을 레퍼런스로 주며 학습을 요청할 때 → 새 프레임 또는 기존 프레임의 사례로 추가
2. 사용자가 확정본(직접 완성한 장표, 모범 사례)을 줄 때 → 그 구조가 풀에 없으면 새 프레임, 있으면 사례·변형 추가
3. 사용자가 프레임 설명·사례를 지적·수정할 때 → 해당 행 수정
4. 보고 자료(PDF, 보고.db 스토리 보기)를 읽다가 풀에 없는 구조를 발견할 때 → 새 프레임
5. 장표 작업을 마칠 때 → 이번에 쓴 프레임 행에 이번 장표를 사례로 덧붙일 가치가 있는지 점검 (사용자가 확정한 경우만)

사용자에게 갱신 여부를 따로 묻지 않는다. 갱신한 뒤 답변 끝에 한 줄로 알린다 (예: "프레임 풀에 F-207 ○○ 추가").

### 어떻게 갱신하나

1. **중복 확인**: 키워드로 풀을 검색한다. 같은 논리 관계·배치면 새 번호를 만들지 말고 기존 행의 사례 열에 `덱 약어 쪽(변형 설명)`을 덧붙이거나 배치 요지에 `변형: …`을 더한다.
2. **새 번호**: 프레임 풀 탭에서 가장 큰 F-번호를 찾아 +1. 번호는 재사용·재배열하지 않는다.
3. **행 추가**: 해당 유형 표의 끝에 행을 넣는다 (docs `insert`, `"as":"blocks"`, 표 id + `"side":"end"`, 6개 셀 모두 채움). 문구는 기존 행 문법을 따른다: 이런 관계일 때 = "~할 때" 한 줄, 배치 요지 = `좌: … / 우: …` 식 배치, 주의 = 검산·각주·오용 주의.
4. **사례 표기**: 덱 약어(프레임 풀 탭 상단 약어표)와 쪽·슬라이드 번호. 새 덱이면 약어표에 행을 추가한다. 사용자 확정본은 `모범N`으로 등록한다.
5. **상세가 필요한 레퍼런스**(사용자가 학습을 요청한 장표 등)는 개요 탭에 F-001처럼 상세 절(골격 / 스토리 / 강조 장치 / 출처)을 만든다.
6. **개요 탭 갱신**: 유형별 번호표의 개수·범위를 고치고, **갱신 이력** 표 맨 위에 `날짜 | 내용` 한 줄을 넣는다.

### 외부 레퍼런스(E-번호) 추가·수정

1. **화면 판독 필수**: PDF 텍스트 추출만으로 배치를 적지 않는다. 도형(쉐브론 패널, 받침, 중괄호, × + 기호, ▶, 캡슐, 재게시 총괄표)은 텍스트에 남지 않는다. `pdftoppm -r 80`으로 전 쪽 접촉 시트를 보고, 항목으로 쓸 쪽은 `-r 110`으로 렌더해 Read로 직접 본다.
2. **PDF 확보 순서**: 샌드박스 `curl`(일부 사이트 허용) → 사용자 PC 내장 브라우저(`mcp__remote-devices__Claude_Browser__*`)로 PDF를 열고 `javascript_tool`에서 `fetch` 후 base64를 **180KB 이하 청크**로 반환(결과는 /tmp/claude-tool-results 파일로 저장됨 → 이어 붙여 디코드) → 404·차단이면 web.archive.org 사본 → 그래도 없으면 사용자에게 파일 첨부 요청. 다른 작업자 탭은 건드리지 않고 자기 탭만 열고 닫는다.
3. **열 규칙**: 시각 장치 열은 "도형 → 논리"로 도형 하나씩. 구조 도형이 없으면 "구조 도형 없음, 표·불릿 배치". 우리 양식 변형은 구조 도형을 살리고, 은유형·그림자·3D·빨간 테두리·말풍선·파란 글자만 허용 장치로 바꾼다.
4. **쪽 번호**: PDF 쪽 기준, 인쇄 번호가 다르면 `PDF p12(인쇄 11)`로 병기.
5. **번호**: 절마다 띠를 나눠 겹침을 막는다. 사용 중인 띠와 다음 새 번호는 외부 레퍼런스 탭 머리말(※ 화면 대조 현황)에서 확인하고, 행을 추가하면 그 머리말과 개요 탭 갱신 이력, 관계 색인 탭의 E-번호 색인을 함께 고친다. 개수와 번호 현황은 이 지침과 표준 지침에 적지 않는다. 병렬 작업자에게 띠를 줄 때는 50개 이상 간격.
6. 화면 대조를 못 한 항목·절은 제목에 "(화면 미확인)"을 붙인다.

### 지키는 것

1. 소스에 없는 구조·수치를 프레임 설명에 넣지 않는다. 확인하지 못한 요소는 "확인 필요"로 적는다.
2. 사례 장표의 쪽·슬라이드 번호는 실제로 열어 본 것만 적는다.
3. 사용자가 이미 쓴 행이나 수정한 문구는 덮어쓰지 않는다. 바꾸어야 하면 그 행 아래에 의견을 남기거나 사용자에게 알린다.
